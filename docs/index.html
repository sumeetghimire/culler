Threat intelligence

Three signals.
One decision.

culler layers three free, real-time data sources to make prioritization decisions that would otherwise require hours of manual research.

KEV

CISA Known Exploited Vulnerabilities

The authoritative list of CVEs with confirmed active exploitation in the wild. Any finding in KEV is an unconditional ACT NOW — no thresholds, no exceptions.

EPSS

FIRST Exploit Prediction Scoring System

Machine-learning probability score (0–1) estimating likelihood of exploitation in the next 30 days. Trained on real-world threat data from hundreds of sources.

SSVC

CISA Vulnrichment / SSVC

Stakeholder-Specific Vulnerability Categorization decision points plus ADP CVSS scores for CVEs that NVD has not yet analyzed — filling the gap left by NVD delays.

Decision engine

Four tiers.
Explicit rules.

Every finding lands in exactly one tier. Rules are deterministic, auditable, and configurable via .culler.yaml.

ACT NOW
In CISA KEV
Confirmed active exploitation. Fix immediately regardless of CVSS or context. No exceptions.
Patch within 24 hours
OUT-OF-CYCLE
EPSS >= 8.8% or SSVC active
High probability of near-term exploitation. Requires an unscheduled fix before the next sprint cycle.
Patch within 7 days
SCHEDULED
EPSS >= 90th pct or CVSS >= 7.0
Elevated risk but not immediately critical. Plan a fix in your current or next sprint.
Patch in sprint cycle
DEFER
Everything else
Low exploitation signal. Monitor and address opportunistically. Not a security priority.
Address as needed

CI/CD & Cloud

Built for pipelines.
Runs anywhere.

culler slots into any DevSecOps workflow. Gate deployments on critical CVEs, upload SARIF to GitHub Code Scanning, or run it as a step in AWS CodePipeline, GitLab CI, or Kubernetes admission checks.

GHA

GitHub Actions

Native uses: sumeetghimire/culler/action@v1 step. Set fail-on: act-now to block merges when actively exploited CVEs are detected. Outputs SARIF directly to GitHub Code Scanning for inline PR annotations.

AWS

AWS & ECR Container Scanning

Scan Amazon ECR images with Grype or Trivy and pipe results into culler. Works in AWS CodePipeline, CodeBuild, and ECS deployment workflows. Output to JSON or SARIF for integration with AWS Security Hub.

K8S

Kubernetes & Docker

Run culler as a container via the official Docker image. Integrate into Helm chart CI, OPA/Gatekeeper admission pipelines, or as a pre-deploy check in ArgoCD and Flux GitOps workflows.

SCA

SBOM & Software Supply Chain

Parse CycloneDX SBOMs generated by cdxgen or Syft to audit your entire software bill of materials. Supports SCA workflows for open source dependency scanning, license compliance, and supply chain security in regulated environments (SOC 2, FedRAMP, PCI-DSS).

.github/workflows/security.yml
- name: Grype container scan
  uses: anchore/scan-action@v3
  with:
    path: "."
    output-format: json
    output-file: grype.json
 
- name: culler triage
  uses: sumeetghimire/culler/action@v1
  with:
    scanner-output: grype.json
    format: sarif
    output-file: culler.sarif
    fail-on: act-now
 
- name: Upload to Code Scanning
  uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: culler.sarif
FAQ

Common questions.

How is culler different from Dependabot, Snyk, or GitHub Advanced Security?

Dependabot, Snyk, and GitHub Advanced Security raise an alert for every detected CVE — often hundreds per project. culler is a triage layer that sits on top of any scanner output and uses real-world exploitation signals (CISA KEV, EPSS, SSVC) to collapse that list to the handful of CVEs that actually need immediate attention. It dramatically reduces alert fatigue without replacing your existing scanner.

Can I use culler to scan AWS ECR or GCR container images?

Yes. Pull the image locally or use Grype/Trivy in registry mode: grype registry:123456789.dkr.ecr.us-east-1.amazonaws.com/myapp:latest -o json | culler. culler enriches findings regardless of where the image lives — AWS ECR, GCR, GHCR, Docker Hub, or any private registry accessible to your scanner.

Does culler work offline or in air-gapped environments?

Yes. On first run culler downloads and caches KEV, EPSS, and Vulnrichment data locally in ~/.cache/culler/. In air-gapped environments pre-populate this cache and run with culler scan report.json --offline. The tool gracefully falls back to cached data when network access is unavailable.

What output formats does culler support for CI/CD integration?

culler outputs: terminal (ANSI color, human-readable), JSON (machine-readable with full provenance for downstream processing), SARIF (upload to GitHub Code Scanning, Azure DevOps, or AWS Security Hub), and Markdown (paste into PR comments or Confluence pages). Use --format sarif for CI/CD pipelines.

How do I suppress a false positive or accepted risk?

Create a .culler.yaml policy file. Add an ignore rule with a reason and optional expiry date. culler will skip that CVE until the expiry date, then surface it again automatically. This gives you an auditable, time-boxed exception workflow compliant with SOC 2 and FedRAMP controls.

Getting started

Up in three steps.

culler downloads threat-intel feeds on first run (~4 MB, one-time) and caches them locally with a 24-hour TTL.

1

Install a scanner

# Grype (recommended)
$ brew install grype

# or Trivy
$ brew install trivy
2

Install culler

# One-liner (Linux / macOS)
$ curl -sSL https://raw.githubusercontent.com/sumeetghimire/culler/main/install.sh | sh

# or via Go
$ go install github.com/sumeetghimire/culler/cmd/culler@latest

# or Docker
$ docker run --rm -i ghcr.io/sumeetghimire/culler < report.json
3

Run it

$ cd your-project/
$ grype dir:. -o json | culler
